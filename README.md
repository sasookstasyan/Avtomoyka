# Автомойка «Центральная» и кафе «Маруся»

Коммерческий сайт на HTML, CSS, JavaScript, Node.js, Express и SQLite (`sqlite3`).
Публичные страницы, заявки на мойку, динамическое меню и единая панель управления
используют один сервер и существующую базу проекта.

## Запуск

Требуются Node.js 20+ и npm. В PowerShell из корня проекта:

```powershell
Copy-Item .env.example .env
# Заполните ADMIN_USERNAME, ADMIN_PASSWORD и SESSION_SECRET в .env
npm install
npm run dev
```

Если файл `.env` уже настроен, не перезаписывайте его. Задайте уникальные
`ADMIN_USERNAME` и `ADMIN_PASSWORD`, а также случайный `SESSION_SECRET` длиной
не менее 32 символов. Не коммитьте `.env` и не используйте секреты из примеров.
При публикации задайте эти переменные в настройках окружения хостинга либо в
GitHub Actions Secrets, если деплой запускается через workflow. Не размещайте
пароль в коде, README или GitHub Pages: статический GitHub Pages не запускает
этот Node.js backend. В production задайте `NODE_ENV=production` и используйте
HTTPS.

- Главная автомойки: <http://localhost:3000/>
- Кафе «Маруся»: <http://localhost:3000/marusya>
- Единая админ-панель: <http://localhost:3000/admin>
- Отдельный редактор меню кафе (доступен после входа в админ-панель): <http://localhost:3000/admin/cafe-menu>
- Проверка backend: <http://localhost:3000/api/health>

## Возможности

- Автомойка: редактируемые услуги, тестовые цены с явной маркировкой,
  онлайн-заявка, статусы записи, контакты, адрес и график.
- Кафе: отдельное оформление, динамическое меню и категории, наличие,
  фотография-URL, редактируемое расписание с любым количеством блюд одного
  типа в каждый день недели.
- В админ-панели расписание недели и отдельный каталог блюд-заготовок доступны
  на одной странице. Каталог рассортирован по категориям; заготовку можно
  добавить к блюдам выбранного дня и типа, не заменяя уже назначенные позиции.
- В стартовом каталоге кафе показаны демонстрационные блюда с фотографиями.
  Названия, цены и наличие помечены как тестовые и редактируются в админ-панели.
- Одна авторизованная админ-панель для обеих организаций; изменения сохраняются
  в SQLite и сразу доступны публичным страницам.
- Отдельная закрытая страница редактора меню кафе доступна по `/admin/cafe-menu`
  из меню админ-панели. Она использует тот же API и базу данных; без сессии
  администратора сервер перенаправляет на `/admin`.
- Кафе не наследует телефон и часы автомойки. Пока они не подтверждены, контакты
  кафе пустые; каталог кафе содержит только явно маркированные демонстрационные
  позиции, не заявленные как реальное меню.
- Картографическая кнопка передаёт адресный текстовый запрос, а не
  неподтверждённые координаты.

В таблице `services` есть демонстрационные тестовые позиции (по одной на
категорию). В описании и интерфейсе они обозначены как тестовые; цена `1 ₽`
является только заглушкой и должна быть заменена/подтверждена. Удалите либо
отредактируйте их перед публикацией. Если стартовый набор ещё не создан, в базу
кафе автоматически добавляются демонстрационные позиции с фотографиями Unsplash.
Цены примеров — тестовые; владелец может изменить либо удалить блюда и добавить
подтверждённое меню через админку.

Ссылка на панель управления намеренно малозаметна: значок-шестерёнка находится
внизу страницы. Это только навигация — доступ к функциям админки всё равно
защищён входом.

## Структура

```text
backend/
  server.js                Express, маршруты и раздача страниц
  database.js              схема и безопасное добавление таблиц SQLite
  routes/central.js        услуги, записи, меню, блюда дня и настройки
  routes/auth.js           вход в панель по учётным данным из окружения
  private/cafe-menu.html   HTML отдельного редактора, отдаётся только после входа
  middleware/              авторизация и CSRF-защита
frontend/
  index.html               главная автомойки
  marusya.html             страница кафе
  admin.html               единая админ-панель
  css/                     публичная тема и тема панели
  js/                      клиенты API и интерактивность страниц, редактор меню
database/
  shop.db                 существующая база; новые таблицы создаются при старте
```

Существующие таблицы и маршруты прежнего проекта сохранены. Новая функциональность
использует отдельные таблицы `services`, `appointments`, `menu_items`,
`dish_library`, `daily_menu`, `categories` и `site_settings` в том же SQLite-файле.
При первом запуске новая таблица `dish_library` заполняется копиями текущих
позиций меню; последующие изменения каталога не переписывают уже опубликованные
блюда дня. При обновлении существующей базы таблица `daily_menu` автоматически
перестраивается для снятия ограничения на одну позицию каждого типа в день;
ранее сохранённые блюда сохраняются.

## Данные и проверка владельцем

В доступных при подготовке проекта открытых поисковых источниках не удалось
надёжно подтвердить карточки организаций или актуальные прайс-листы: результаты
картографического поиска не предоставили читаемых сведений, а поисковые
результаты не содержали подтверждаемой карточки. Поэтому фотографии,
ассортимент, услуги, цены, часы кафе и телефон кафе не выдаются за реальные.

Адрес автомойки `Иваново, ул. Багаева, 5`, адрес кафе с указанием 1-го этажа,
название автомойки, телефон `+7 (4932) 21-66-90` и режим `ежедневно
08:00–21:00` внесены как исходные данные из задания, но независимо не
подтверждены; проверьте их у владельца. Слоган, текстовые описания,
иллюстративные изображения и примеры категорий являются элементами оформления,
а не заявлением о проверенных свойствах заведения. Визуальные образы кафе —
иллюстрации, не фотографии интерьера или вывески.

Иллюстративные фотографии автомобилей и блюд загружаются с Unsplash и не
показывают автомойку или кафе; лицензия Unsplash разрешает коммерческое
использование изображений: <https://unsplash.com/license>. Фоновая карта —
авторская схема, не точный план и не указание координат; маршрут строится
картографическим сервисом по адресу.

## Безопасность и хранение

Используется `sqlite3`, не `better-sqlite3`. Для входа применяется существующая
сессионная авторизация проекта, rate limit, CSRF-проверка и SQLite session
store. Перед эксплуатацией смените тестовые учётные данные, включите HTTPS,
задайте production session secret и настройте резервное копирование
`database/shop.db`.
